LicentieKluis
Rust-client + webportaal

Leveringsstatus: de Rust-client is geschreven, maar in deze omgeving niet gecompileerd: Rust/Cargo ontbreken en downloads zijn geblokkeerd. Daarom bevat dit pakket geen Rust-.exe. Het bouwscript maakt die op een pc met de benodigde ontwikkeltools, en stopt als een test of build faalt. De server is wel gecompileerd. De bestaande 17 .NET-tests en 8 tests van de webinterface-logica zijn geslaagd; die laatste gebruiken een gesimuleerde DOM/API. Een echte browser-/netwerktest, de Rust-tests en de LXC-installatie zijn nog niet uitgevoerd.

Het webportaal is in deze versie alleen voor bekijken. Toevoegen, bewerken en verwijderen doe je in de Windowsclient. Licentiehouders krijgen geen eigen inlogrecht: één serverbeheeraccount kan alle licenties zien.

1. De Rust-client bouwen

Alleen op de bouw-pc zijn nodig:

  1. Rust met Cargo, standaard Windows MSVC-toolchain.
  2. Visual Studio Build Tools met de workload Desktop development with C++ en een Windows SDK.
  3. Internet voor het ophalen van Rust-crates tijdens de eerste build.

Pak de map volledig uit en dubbelklik op Build-Rust.cmd. Het script maakt eerst een Cargo.lock, voert de Rust-tests uit en bouwt daarna de release. De executable verschijnt na een geslaagde build hier:

output\Windows-Rust\LicentieKluis-Rust.exe

De uiteindelijke gebruikers-pc heeft Rust, Cargo en Visual Studio niet nodig. De client gebruikt de Windows-API en de gedeelde Windowsvoorzieningen voor TLS. Het script linkt de C-runtime statisch. De exacte bestandsgrootte is nog niet gemeten; het script toont die na het bouwen. De eerder genoemde 2–10 MB blijft een schatting.

Optioneel bevat .github/workflows/build.yml een Windows-/Linux-buildworkflow. Plaats de inhoud van deze map als repositoryroot om die te gebruiken. Er is door deze levering geen repository aangemaakt of code gepubliceerd. Cargo.lock ontbreekt bewust zolang dependencies niet zijn opgehaald; bewaar de tijdens je eerste build gegenereerde lockfile bij de broncode voor herhaalbare builds.

2. Windows gebruiken

  1. Start de gebouwde executable. Voor de eerste kluis kies je minimaal 14 tekens en vul je ook Herhaal in.
  2. Voeg links een gebruiker toe via het veld Gebruikersnaam en Toevoegen.
  3. Kies Nieuwe licentie, voer software/code in en selecteer de licentiehouder.
  4. Voeg per installatie een platform en apparaatnaam toe met +. Eén licentie kan meerdere apparaten en platforms hebben.
  5. Klik Opslaan voordat je een andere licentie selecteert of synchroniseert.
  6. Gebruik links de gebruikersselectie en boven het overzicht de zoek- en platformfilters.

Gegevens staan afzonderlijk van de oude client in %LOCALAPPDATA%\LicentieKluisRust\vault.lkv. De originele .NET-kluis wordt niet aangepast. Bij vergrendelen verdwijnen de getoonde licentiegegevens uit het venster. Het lokale wachtwoord staat niet in de back-up en kan niet worden hersteld als je het vergeet.

Code tonen maskeert de code na 30 seconden opnieuw. Kopiëren wist het huidige klembord na 30 seconden als het nog dezelfde inhoud heeft. Windows-klembordgeschiedenis en andere klembordapps kunnen een kopie bewaren. Het webportaal kan het klembord niet betrouwbaar automatisch wissen.

3. Bestaande gegevens meenemen

Via de server: maak een nieuwe lokale Rust-kluis, vul het HTTPS-serveradres en je bestaande serveraccount in en klik Aanmelden. Bij de eerste koppeling bevestig je dat lokale gegevens naar deze server mogen worden verzonden. Vanaf dan synchroniseert de client elke minuut zolang hij aangemeld is en er geen onopgeslagen formulier of conflict openstaat.

Via een back-up uit .NET 0.1: maak in de oude client een .lkv-back-up. Vul in de Rust-client onderaan het wachtwoord van die back-up in en klik Herstellen. De Rust-code ondersteunt het bestaande LKV1-formaat en de PascalCase-velden. Een echte .NET-testback-up met uitsluitend voorbeeldgegevens is meegeleverd in fixtures en wordt door de Rust-tests gecontroleerd zodra je die bouwt. De Rust-import is hier nog niet uitgevoerd. Bewaar altijd je oorspronkelijke back-up.

Rust-back-ups gebruiken camelCase JSON en worden niet teruggelezen door de oude .NET-client. Gebruik voor overdracht terug naar de oude client de server. Bewerk een gekopieerde offline kluis niet onafhankelijk in twee clients zonder synchronisatie.

4. Server installeren of bijwerken

Voor een nieuwe server: een aparte unprivileged Ubuntu 24.04 LTS x86_64-container op Proxmox, met een vast IP-adres. Startvoorstel 2 vCPU, 1 GB RAM, 8 GB disk; geen gemeten minimum. Kopieer de volledige map naar /root/LicenseVault-Rust. Voer uit binnen de container:

cd /root/LicenseVault-Rust
bash scripts/install-lxc.sh

De installer vraagt het IP-adres/de DNS-naam en maakt een beheeraccount aan. Hij installeert de ASP.NET Core-runtime, de meegeleverde server en Caddy voor HTTPS. Docker is niet nodig. Het script maakt de Proxmox-container zelf niet aan.

Voor een bestaande 0.1-installatie: maak eerst een back-up en kopieer vervolgens het nieuwe pakket naar de container:

cd /root/LicenseVault-Rust
bash scripts/backup-server.sh /root/kluis-backups
bash scripts/update-server.sh

Het updatescript gebruikt de inhoud van ServerBin, inclusief wwwroot. De gegevensmap /var/lib/licentiekluis, encryptiesleutel en het beheeraccount blijven behouden. De oude programmaversie wordt bewaard. Een bestaande .NET-client kan de synchronisatie-API blijven gebruiken.

5. Webportaal openen

Open vanaf een pc, tablet of telefoon binnen hetzelfde netwerk:

https://HET-IP-ADRES-VAN-JE-LXC/

Gebruik exact het IP-adres of de DNS-naam die bij installatie is ingesteld. Log in met hetzelfde serveraccount als in de Windowsclient, niet met je lokale kluiswachtwoord.

  • Filter op gebruiker, Windows/Linux/macOS, software of apparaatnaam.
  • Codes worden pas afzonderlijk opgehaald als je op Code tonen of Kopiëren klikt.
  • Klik Vernieuwen om recent gesynchroniseerde gegevens op te halen.
  • Na 15 minuten inactiviteit wordt het portaal vergrendeld.
  • De sessie staat alleen in het browsergeheugen, niet in localStorage of cookies. Herladen vraagt opnieuw aanmelden.
  • Uitloggen wist de weergegeven gegevens en trekt de serversessie in als de server bereikbaar is.

Het portaal toont uitsluitend de laatst gesynchroniseerde servergegevens. Nieuwe offline Windowswijzigingen verschijnen pas na synchronisatie. De webpagina is alleen bereikbaar als de LXC en de serverdienst draaien.

HTTPS-certificaat

Bij installatie maakt Caddy een eigen lokale CA. Kopieer alleen /root/licentiekluis-ca.crt naar Windows en voer uit:

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Trust-ServerCertificate.ps1 -CertificatePath C:\Pad\licentiekluis-ca.crt

Vergelijk de getoonde vingerafdruk met die op de server:

openssl x509 -in /root/licentiekluis-ca.crt -noout -fingerprint -sha1

Vertrouw de CA ook op andere apparaten waarmee je het portaal wilt gebruiken. Omzeil certificaatcontrole niet. Gebruik het portaal binnen je netwerk of via je VPN; stel deze testversie niet rechtstreeks bloot aan internet.

6. Back-up en herstel

Back-up in de Rust-client exporteert de kluis versleuteld met het huidige lokale kluiswachtwoord. Herstellen vraagt vooraf het wachtwoord van de gekozen back-up en bewaart de huidige gegevens als herstelkopie. Terugzetten van een oude lokale back-up draait de server niet terug; nieuwere servergegevens worden bij synchronisatie weer opgehaald.

De serverback-up bevat ook secrets.json, de sleutel waarmee de serverkluis geopend kan worden. Beveilig die back-up en gebruik versleutelde back-upopslag. Maak daarnaast Proxmox/PBS-back-ups van de volledige container zodat ook de Caddy-CA wordt behouden.

8. Nieuw in 0.3: licenties per e-mail delen

Selecteer maximaal 50 licenties, vul één ontvanger en een onderwerp in en controleer het voorbeeld. Iedere licentie krijgt een eigen blok met softwarenaam, optionele versie en de volledige code. Notities en apparaatnamen gaan niet mee.

Server: eenmalig instellen

Werk de server eerst bij met bash scripts/update-server.sh vanuit de uitgepakte nieuwe versie. Voer daarna binnen de LXC als root uit:

bash scripts/configure-mail.sh

Vul SMTP-host, poort (standaard 587), afzender, gebruikersnaam en wachtwoord/app-wachtwoord in. STARTTLS is verplicht. Poort 465 en OAuth worden niet ondersteund. Je mailprovider of eigen relay moet deze verzendwijze toestaan. De instellingen worden versleuteld opgeslagen. Het script herstart de service; er wordt geen testmail verstuurd.

Webinterface

  1. Log in en vink de gewenste licenties aan. Je selectie blijft behouden bij filteren; controleer daarom ook de selectielijst.
  2. Vul het ontvangeradres en onderwerp in.
  3. Klik op het e-mailvoorbeeld en controleer alle volledige codes.
  4. Klik op Definitief versturen.

Windows

  1. Open Licenties mailen. De lijst bevat de licenties van de geselecteerde gebruiker, of alle licenties bij het totaaloverzicht.
  2. Klik de gewenste licenties aan en vul ontvanger en onderwerp in.
  3. Klik Voorbeeld maken.
  4. Kies Via server versturen (aanmelden en synchroniseren vereist), of Open eigen mailprogramma. Bij die laatste optie klik je zelf op Verzenden in je standaard mail-app.

De eigen mail-app kan ook vanuit een offline kluis worden geopend. Werkelijke verzending hangt af van je mail-app en internetverbinding. Bij een te grote mailto-koppeling kies je minder codes of verzending via de server.

Status en bijwerken

“Aangeboden aan de mailserver” betekent nog geen ontvangstbevestiging. Bij een onzekere status controleer je eerst de ontvangst. Hetzelfde verzoeknummer wordt door de server niet twee keer verstuurd; een nieuw voorbeeld krijgt een nieuw nummer. Er is geen automatische mailherhaling. Wijzigingen aan een licentie na het voorbeeld blokkeren verzending van een verouderde selectie.

Neem bij serverback-ups de volledige datamap mee, inclusief smtp.lkv, mail-log.lkv en secrets.json. Gebruik geen oudere server tegelijk met de nieuwe clientfunctie. De bestaande kluisgegevens blijven compatibel.

Validatie: server gecompileerd, 25 opslag/synchronisatie/mailcontroles en 13 webinterfacecontroles met gesimuleerde API. Rustclient nog niet gecompileerd: Rust-toolchain ontbreekt. Geen echte SMTP-verzending of LXC-installatie getest.
